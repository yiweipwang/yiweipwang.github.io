Sound Space, rebuilt in JavaFX

A parody of the rhythm game Sound Space with one rule I set for myself: no hand-authored levels. The game has to listen to the song and build the level itself.

Year
2024
Type
Game + audio analysis
Stack
Java, JavaFX, Python
Code
GitHub

The constraint that made it interesting

Most rhythm games ship with charts a human placed note by note. I wanted arbitrary songs to be playable, which turns a game project into a signal-processing project: given an audio file, find the beats, and find them accurately enough that the gameplay feels fair at speed.

How it works

A Python pipeline analyzes the audio offline — detecting beat onsets and their timestamps — and emits a chart the Java game consumes. At runtime, JavaFX renders the note field while a timing system keeps the chart locked to audio playback, scoring hits by how close the player's input lands to each detected beat.

The hard part wasn't detection, it was synchronization. Audio playback, the render loop, and input events each live on their own clock, and a rhythm game is unplayable if they drift by even a few tens of milliseconds. The fix was treating the audio position as the single source of truth and scheduling everything else — note spawning, hit windows, animations — relative to it, rather than to wall-clock time or frame count.

What I took from it

Cross-language plumbing is a real skill: defining a clean chart format between the Python analyzer and the Java game made each side simple, and made the analyzer swappable. And real-time programming taught me a respect for clocks that no coursework had — "what time is it?" is a surprisingly deep question inside a game loop.
