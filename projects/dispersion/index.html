Volatility dispersion backtest

An end-to-end options backtest implementing four variants of volatility dispersion — from classic variance swaps to 0DTE-driven signals — with a point-in-time data discipline, full transaction cost model, six validation gates, and an auto-generated comparison tearsheet.

The idea

Volatility dispersion exploits the tendency of index implied volatility to trade rich relative to the weighted sum of its constituents' implied vols. The trade is to sell index variance and buy constituent variance — collecting the "correlation premium" that options market-makers charge for the diversification protection embedded in index puts.

The project implements four distinct ways to express this idea, each with different Greeks profiles and market conditions that favor them.

Four variants

V1 is classic variance dispersion: replicate variance swaps on the index and each constituent using the model-free replication formula, then go short index variance and long constituent variance weighted by market cap. V2 translates the same trade into implied-correlation space — backing out the implied correlation from the index and constituent surfaces and trading it directly against realized correlation. V5 enters when the realized-vs-implied correlation spread crosses a threshold, sizing the position by the width of that spread. V6 uses 0DTE index options to express the short-correlation view at much shorter time horizons, refreshing the hedge daily.

Architecture

The codebase has 14 modules, each with a single responsibility: data loading, implied surface construction, Black-Scholes Greeks, variance swap pricing, basket weight calculation, signal generation, execution simulation, P&L attribution, risk metrics, cost modelling, validation gates, and tearsheet generation. Public APIs use standard Python types throughout — no internal dataclasses leak between layers, which made unit-testing straightforward and the modules reusable independently.

All thresholds and hyperparameters live in YAML config files. Running a different variant requires only a config change, not a code change. make all runs all four required variants and generates the comparison tearsheet PDF in under 60 minutes on a laptop.

Point-in-time discipline

The backtest window (Jan 2022) is cleanly separated from the estimation window (Oct–Dec 2021). All loaders enforce the as-of date from the date column; the 21-day realized correlation entering Jan 3 is computed on December data only. Every run writes a metadata JSON with the git SHA, config hash, data hashes, and timestamp so results are exactly reproducible.

Validation

Six validation gates run as pytest cases: gamma and vega within 0.5% of a vendor reference, variance swap strike within 2 vol points of ATM IV, implied correlation in the [0, 1] plausibility range, a look-ahead audit confirming no future data enters any signal, a cost sanity check, and a full reproducibility gate. All six pass across all four variants.

What I took from it

Building the variance swap replication from scratch — rather than using a framework — forced a deep engagement with the math: the log-contract approximation, the discretization error in the strip of options, and the boundary treatment for deep OTM strikes. The implied-correlation back-out is similarly tricky to get right numerically; I verified the round-trip error to under 1e-6. The project also sharpened my instinct for look-ahead contamination, which is easy to introduce accidentally when estimation and backtest windows share the same DataFrame.
